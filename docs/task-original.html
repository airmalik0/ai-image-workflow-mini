Тестовое: AI Image Workflow Mini

Нужно собрать небольшой node-based редактор и провести одну реальную AI-генерацию через backend. Тест проверяет frontend, backend, работу с AI API и понимание выполнения графа.

Frontend architecture: архитектура проекта — Feature-Sliced Design (FSD). Ожидаем понятное разделение ответственности между слоями и отсутствие бизнес-логики в случайных UI-компонентах. Не требуется «идеальный FSD» — важнее осмысленная структура проекта.

9. Canvas — визуальный редактор ⭐

Задание со звездочкой

Полноценный визуальный Canvas необязателен. Если успеваете — реализуйте node-based редактор через React Flow / xyflow или другую готовую библиотеку. Писать canvas engine с нуля не нужно.

Prompt

Текстовый ввод.

Image Input

Загрузка изображения.

Generate Image

Генерация через AI.

Edit Image

Редактирование изображения.

Result

Предпросмотр результата.

Если делаете Canvas, желательно поддержать: add, move, connect, delete, branching, selection.

Typed ports: достаточно типов text и image. Несовместимые соединения нужно блокировать.
Важно: отсутствие полноценного Canvas не считается невыполненным тестовым. Но graph definition, dependencies, branching и parallel execution остаются обязательной частью — workflow можно представить как данные и управлять им без визуального редактора.

10. AI integration — интеграция нейросети

Нужен хотя бы один реальный вызов image-generation API.

Browser
   ↓
Backend
   ↓
AI API
   ↓
Backend
   ↓
Result node
API key не должен попадать во frontend.
  • text → image;
  • отображение результата;
  • loading/error state;
  • timeout/error handling.

Edit Image можно реализовать, если выбранный API поддерживает редактирование. Иначе достаточно описать подход в README.

11. Preset — готовый набор настроек

В продукте есть Preset: готовый набор референсов и правил для генерации изображения. Полноценный Preset Editor в тестовом не нужен.

{ "id": "preset-demo", "name": "Premium 3D", "mainPrompt": "premium minimal 3D visual...", "negativePrompt": "clutter, noisy background...", "references": [ "/references/ref-1.png", "/references/ref-2.png" ] }
User Prompt
     +
Selected Preset
     ↓
Request Builder
     ├── mainPrompt
     ├── negativePrompt
     └── references
            ↓
          AI API
Важно: Preset должен быть отдельной сущностью в data model, а не логикой, спрятанной внутри UI-компонента.

12. Parallel execution — параллельное выполнение

Обязательно
                   ┌→ Generate A
Prompt ────────────┤
                   └→ Generate B

Независимые ветки должны иметь возможность выполняться одновременно.

  • Graph definition — описание графа;
  • Graph execution — выполнение графа;
  • Dependencies — зависимости;
  • Parallel branches — независимые ветки.

13. Jobs и состояния

Job — отдельная задача выполнения, например один вызов Generate Image.

idle

Не запускалась.

queued

Ждет выполнения.

running

Выполняется.

success

Готово.

error

Ошибка.

POST /runs
    ↓
{ runId }

GET /runs/:runId
    ↓
queued / running / completed / failed

Допустим polling, SSE или WebSocket.

Retry — повтор failed node должен быть доступен.
